Text & objects

Text styles (the work's typography)

Every text can follow a named style — Dialogue, Thought, Shout, Narration ship with a new work at Japanese Q-size conventions. Pick one in Tool Property ▸ Text style before typing (new text carries it) or with a text selected (it snaps to the style). The point is the edit: open Styles…, change the size or font, Apply — every text on the page that follows the style reflows in ONE undo step, and Re-style every page in the work pushes it chapter-wide. In Clip Studio, changing dialogue size mid-chapter means fixing every page by hand; here it is one slider.
Other pages are saved directly. The whole-work button writes the other pages' files in place; undo covers the open page only — same honesty as batch operations.
A style pins typography, not placement. Font (if the style sets one), size, colour, edge, letter and line spacing follow the style; position, rotation, orientation, furigana and per-character runs stay yours. Editing a styled text's size by hand is fine too — it simply snaps back the next time the style is applied.

The Object key cycles the stack

Press O again to move onward. With something selected in the Object tool, pressing the Object key again moves the selection through everything stacked under your click — in the same order clicking would find them: text first, then effect-line runs, then balloons, then frames. Shift+O steps back; both wrap around. The status bar names each hop (text → balloon (2 of 3 here)). Cycling only moves the selection — nothing is edited, nothing is undoable.
Switching from the Text tool to Object selects the balloon. With a text selected, pressing O from the Text tool hands the selection to the balloon containing that text — the bubble's vertices and handles, ready to drag. If no balloon contains it, the text stays selected.

Turning a balloon turns its lettering

Rotate a drawn bubble and the text inside it comes with it — still text. Every text box whose centre sat inside the balloon swings around with it and is re-set at the new angle by the font engine. Nothing is flattened into pixels: click it afterwards and keep typing, restyle it, change its furigana. (This is the thing you cannot do in Clip Studio, where a text layer has to be rasterised before it can be turned and the lettering then can never be edited again.)
Undoing that takes two steps, and only a drawn bubble does it at all. The bubble and the lettering live on different layers and history is kept per layer, so Ctrl+Z takes back the text first and the balloon second — the status line says how many texts came along. An ellipse or rounded-rectangle balloon cannot be tilted at all (see Comic), so turning one moves no lettering either. Text on a hidden or locked layer is left where it is.

Undo while you are typing

The IME follows your caret. While composing Japanese, both the composition string and the candidate list sit at the caret and move with it — the candidate list one line below, so it does not cover the text you are reading. (The composition still renders in the OS's default style; drawing it inline in the box is future work.)
Ctrl+Z inside a text box steps back through your edits, not out of the box. Typing collapses into word-sized steps — a run of characters undoes together, while a space, a newline, a deletion, a style change or a reading each get their own step. So does anything you change in Tool Property while the caret is in the box: a font, an alignment, a furigana setting — and a whole slider drag counts once, not once per frame.
The press that runs out of edits closes the box and stops there. When there is nothing left to undo inside the box, Ctrl+Z ends the session; if the session changed anything, that same press also takes the box back, which is the single step the document's own history keeps for it. A session that ends where it started has nothing in that history, so the press only puts the caret away and the drawing behind it is left alone — press again to undo what you did before you opened the box.

Furigana (ふりがな)

Select the kanji inside the text, type the reading into Tool Property ▸ Furigana, press ルビ. An empty field clears the reading; the field's grey hint shows whatever reading the caret is already sitting inside, so you can see one without hunting for it on the canvas. Readings are set at half the base size — that is what JIS specifies, so it is fixed and not a slider. In vertical text the reading goes to the right of the column, in horizontal above the word.
An annotated text box spaces its lines further apart than an unannotated one, because the readings need somewhere to sit — a text set to a specific Line spacing keeps exactly the spacing you asked for, and only Auto makes room automatically. Text with no readings is laid out exactly as before, to the pixel.
Tool Property ▸ Furigana carries the reading settings: Size, Gap, Adjust and Along. They apply to the whole text item, not to one reading — as in Clip Studio, and because a balloon whose two readings are set differently is a balloon with a mistake in it. Size defaults to 50 % of the base text, which is what JIS specifies; Clip Studio ships 67 %, so a page set there needs this turned up to match. Gap is the distance from the base text, Adjust slides the reading along the word, and Along decides whether a short reading sits centred on its word (the usual) or against one end.
Readings follow the characters they belong to as you edit: typing in front of an annotated word carries the reading along, typing inside it extends the reading's range, deleting part of the word shrinks it, and deleting the whole word removes the reading with it. Known limit: if an annotated word wraps across two lines, the reading is drawn against the first line only.

Numbers in vertical text (縦中横)

Select the number while editing, then press 縦中横 in Tool Property ▸ Style. It sits with B/I/U because it behaves like them: a toggle over the selected characters, shown pressed when they are already upright, and pressing it again lays them back down. A selection that is only partly upright counts as off, so the press finishes the job rather than undoing the half that was done. The button is greyed in horizontal text, where the setting would mean nothing.
Characters marked as 縦中横 are set upright and side by side, inside one character cell of the column. That is how a number reads on a printed Japanese page — 22時, 3人, 第1話 — and it is exactly what a vertical line does not do by itself: left alone the text engine lays Latin characters on their side and stacks them down the column, so 22 arrives as two fallen digits. A marked run takes exactly one cell however many characters are in it, and its characters are centred in that cell.
Two digits are set at full size; three or four are shrunk to fit the column. A digit is around six tenths of a character wide and a column is about one and a half, so a pair fits with room to spare and nothing is scaled — and a pair is what 縦中横 is conventionally used for. A longer run is scaled down as a group, where a Japanese typesetter would instead narrow the glyphs without making them shorter; the text engine cannot do that to part of a line, so the group simply gets smaller. A text box holding nothing but the number shrinks it too, for a duller reason: with no other character on the line there is nothing to set the column's width by, so the pair is squeezed into a single cell.
It does nothing in horizontal text. 縦中横 means "horizontal inside vertical", so a run left on a box you later turn horizontal is ignored rather than made to mean something else. Marked runs follow their characters as you edit, exactly as readings and font overrides do, and two runs that end up touching become one cell — 2 and 2 marked separately are still 22 in one square.

Auto 縦中横

Tool Property ▸ Text direction ▸ 自動縦中横 stands short numbers upright without you selecting anything. Pick how long a run may be — off, 1, 2, 3, 4 — and every run of half-width letters or digits up to that length is set upright on its own: 第1話, 22時, 3年. New text boxes start at 2. The row is greyed in horizontal text for the same reason the 縦中横 button is.
A run is taken whole or not at all. With the limit at 2, "223" is left lying down rather than set as an upright 22 with a stray 3 after it — half a number standing up is worse than none. Runs are measured between non-alphanumeric characters, so a line break, a kana or a space ends one; full-width ２２ is already upright in a column and is never touched.
Nothing is written into the box — the runs are worked out afresh every time it is drawn. Turning the setting back to off therefore restores the page exactly, and typing a third digit into a pair takes the cell apart again instead of leaving a two-character cell with a digit hanging off it.
Auto cannot be cancelled for one span; the 縦中横 button only clears runs you marked by hand. A run you marked yourself wins over anything Auto found in the same characters, but there is no way to tell Auto to skip a particular number. To lay one back down, set 自動縦中横 to off for that box and mark the runs you do want. Clip Studio has the same hole and gives the same answer.

Two fonts in one balloon

Select characters while editing, then pick a font — it applies to the selection, not the whole box. With nothing selected the picker sets the item's font as it always did (and the default for new text). This is the same rule the B/I/U buttons follow. It exists because a Japanese balloon font rarely has Latin worth reading, so the English shout, the SFX or the name on a sign wants its own face inside otherwise Japanese text. A font set over part of an existing override splits it instead of replacing it: set a line in one face, then three characters of it in another, and the first face still holds either side. Picking the item's own font for a selection clears the override rather than storing a duplicate one — otherwise changing the box's font later would leave islands of the old face behind with nothing on screen to explain them; that too takes back only the selection, not the run around it. A furigana reading is set in whatever font its base characters use.

Style runs and the story editor

Script edits reset character styling when the length changes. Editing a field's text through the Story Editor keeps per-character styling (bold, colour, size) only while the text length stays the same; any length-changing edit resets the style runs to the field's defaults. Same-length edits (retyping a character) keep them.
Alignment and spacing are item-level. Row alignment and line spacing apply to the whole text item, not to a selected range — DirectWrite has no per-range paragraph alignment. Strikethrough and underline work in vertical text, where CSP hides them.
